# InfoHub native iOS

Native SwiftUI rewrite on `ios`. The React Native app and Android sources remain in place. Open **InfoHub.xcodeproj**, select the **InfoHub** scheme, then run on an iPhone or iPad simulator. No Metro, CocoaPods, or third-party runtime is required.

From the `tops-mobile-app` directory, build and launch on iPhone 18 Pro Max with:

```sh
npm run ios:native
```

To choose another installed simulator, use `npm run ios:native -- "iPhone 18 Pro"`.
The command reuses build output and restarts the app with the latest code. It does
not package or upload a release. It opens Device Hub or Simulator from the active
Xcode installation, without relying on the app's registered name.

## Platform and design

- Minimum iOS 17; Liquid Glass navigation surfaces on iOS 26+. The bottom bar uses the original Ionicons with icon-left/text-right items; the mini player sits above it. Earlier systems use standard materials.
- The mini player keeps only its 44pt play/pause control; cover/title opens the full audio detail page. The detail page's sole **结束播放** action is fixed at the bottom center above the home-indicator safe area, outside the scrolling content, with a 44pt-minimum touch target. A native safe-area inset lets playback controls scroll clear of the action. It reuses `PodcastPlayer.stop()` to stop audio, dismiss the detail page, remove the bar and clear the saved current episode without deleting per-episode progress. Its **收起** control only dismisses the detail page and retains playback. Stopping updates the shared footer budget and stock heatmap height in place.
- Three destinations: Discover, Subscriptions, and My Account. Native navigation stack, sheets, reordering and pull to refresh. Discover has a single compact channel bar, without an additional generic hero or search header.
- The system launch storyboard reuses the original `assets/welcomePage.png`: a white canvas, orange sun/mountain logo and striped footer. It scales to fit without cropping or stretching, retaining white in both appearances. There is no timed splash overlay or network-dependent launch delay; the project generator preserves the storyboard and artwork resource.
- App typography is fixed to the standard (`.large`) baseline in both the SwiftUI root and its window-scene content-size trait, independent of system text-size changes, including accessibility sizes. The scene override also covers presented UIKit/SwiftUI hosts rather than relying on sheet environment inheritance. This applies to channel rails, feeds, navigation, settings and presented sheets. The in-app reading-size control retains Small/Standard/Large multipliers; its legacy `native.readingSize = system` value now means Standard without rewriting saved preferences. VoiceOver, appearance, reduced motion/transparency and minimum touch targets remain available. Embedded source websites retain their own typography and pinch zoom.
- The bottom-navigation selection plate is capped at 108pt wide at the fixed standard text size, without shrinking its full-width touch target. Channel plates retain their 4pt horizontal inset; both keep a 3pt vertical inset, 44pt minimum touch targets and existing spring transitions.
- Edge-to-edge editorial layouts: an inset glass channel rail above open hot lists/tables, article/video artwork, podcast rows with independent playback, and readable Arena metric cells. There are no enclosing rounded reading panels; glass is reserved for navigation, the mini player and playback controls.
- Swipe horizontally or use the channel menu to switch channels. Each channel keeps its vertical reading position. List spacing is fixed to standard, ignoring legacy saved compact/spacious preferences; My retains appearance and reading-size controls.
- All news pages, including editorial overview and RSS, share a 44pt glass back-to-top button after scrolling down 240pt. It clears the measured player/navigation footer, returns to the channel's complete header, and respects reduced motion. The action interrupts the nearest native feed's scrolling before returning to its inset-aware top, rather than losing a proxy request during momentum. A non-interactive weak view anchor leaves native delegates, horizontal paging and chart gestures unchanged; the proxy remains a fallback if the anchor is unmounted.
- The complete stock heatmap uses the actual page height and measured player/navigation footer instead of a fixed 600pt chart. The footer reports its current geometry directly, including height decreases when the mini player disappears, so the mounted heatmap reclaims that space without changing channels. Reader navigation still retains the last visible footer budget to preserve feed scroll positions. Its timestamp shares that height budget; the bottom explanatory sentence is removed. Summary heatmaps retain 240pt height and twelve sectors. Opaque light/dark red-rise/green-fall palettes preserve intensity bands and readable change values, rather than fading light fills over black.
- Native iOS 1.4 (26) adds GitHub Trending (daily/weekly/monthly), AI Analysis (intelligence/speed/task cost), and the extension-style editorial overview. Special-channel endpoints refresh in parallel and keep last successful data on individual failures. New channels merge into local/cloud-restored settings without resetting opt-outs, order, RSS or unknown fields. Codex Radar and the extension-retired AI News are not exposed in the mobile UI. Legacy RN/Expo/Android release configuration remains unchanged.
- The editorial overview has no repeated brand/page heading or category titles. Sspai, 36kr, NN/g and RSS form continuous article rows; a 15pt source logo and source name sit together above the headline in its text column, following the extension rather than occupying a separate leading column. There is no standalone article-source heading or extra channel gap. Existing headlines/metadata remain intact, with 44pt source targets and independently tappable covers/text for reading. Sina and TIOBE show five items, the market map twelve sectors, and other lists up to four items; TIOBE reuses the complete channel's table header (current/previous-year rank dates, language, ratings and change), including its stacked accessibility layout. AI Analysis retains all intelligence-chart models with horizontal scrolling, matching the extension rather than truncating at four. Available items are never padded with placeholders. Full channel feeds, ordering and subscription data remain unchanged.
- Overview article thumbnails use a common 140×93⅓pt landscape frame (3:2), independent of text height. They start beside the visible source logo/name, excluding the shortcut's transparent top padding while retaining its 44pt touch target. The row accommodates whichever is taller: the fixed-ratio cover or the natural source/headline/metadata column. Artwork scales proportionally and crops only when the source ratio differs; 36kr removes its old height-balancing transparent spacers and uses an 8pt headline/metadata gap. Accessibility text retains its stacked layout with 3:2 overview covers; complete channel feeds retain their original dimensions/ratios. Overview rows omit secondary summaries while retaining source, headline and publication/author metadata; complete channel summaries remain unchanged.

These scenarios and their actor-backed responses are excluded from Release. Do not use a personal simulator/account for subscription-write tests or launch a fixture-populated simulator against the real API.

## TestFlight release

On this Mac, install the worktree-specific hooks once, then push the native branch:

```sh
python3 ios-native/tool/local_testflight.py install
git push origin ios
python3 ios-native/tool/local_testflight.py status
```

After an accepted push, the hooks queue a local TestFlight release in the
background. Git has no post-push hook, so this pairs `pre-push` with the
committed update of the local tracking ref. The push prints the log path.
Failed pushes, other branches, other remotes and `--no-verify` do not start a
release. Install the hooks separately in each worktree; pushes from another
computer do not start this Mac's release. Existing hooks are not overwritten.
If needed, installation adds an `origin` fetch refspec for this branch so Git
updates its tracking ref after a successful push; other refspecs are retained.

The local release tests and builds the exact pushed commit, excluding uncommitted
changes. Contract tests run on a temporary simulator that is deleted afterward.
Releases run one at a time; Xcode automatically signs the existing InfoHub app
using team `UPDM24DCXU`. The local build counter starts above both the project
number and the last confirmed GitHub TestFlight build, 1.4 (30), and increases
for each attempted archive. Xcode may adjust a conflicting number during upload.
If a different Mac or the manual GitHub job uploads a build, synchronize this
counter to at least the latest TestFlight build number before the next push.
Do not run releases from multiple machines at the same time:

```sh
python3 ios-native/tool/local_testflight.py seed-build-number <latest-number>
```

Xcode must be signed in to the team; keep the Mac awake and online during the build. A
successful upload still needs Apple processing, and internal testing-group access
must be checked separately. Xcode's local upload does not update the manual
Fastlane job's TestFlight testing notes. Local logs are under
`ios-native/build/local-testflight`.
An upload failure does not undo the push. Run
`python3 ios-native/tool/local_testflight.py retry [commit]` to retry a pushed
commit, or `verify [commit]` to test and export without uploading. The archive
and export are temporary; only logs and upload markers are retained. Already
uploaded commits are skipped. `uninstall` removes this worktree's hook setting;
it leaves the added tracking refspec in place.

Pushes to `main` retain the React Native/Expo GitHub release. The native GitHub
job remains available through manual dispatch: select `implementation: native`;
`validate_only` runs tests and an unsigned archive without uploading.

The manual native job uses the checked-in Xcode project, not Expo, Metro, CocoaPods or
`generate_project.rb`. Fastlane is pinned by `Gemfile.lock`; it verifies the
existing InfoHub App Store Connect ID `6739748229`, increments the build above
the current TestFlight train and the local baseline, uses a dedicated
`InfoHub Native AppStore` profile, then waits up to 20 minutes for Apple to process
the upload. It never submits public App Store review or invites external testers.
Internal testing-group access must be verified separately after processing.

Required repository Actions secrets (do not commit them):

| Secret | Value |
| --- | --- |
| `APPSTORE_KEY_ID` | Existing App Store Connect API Key ID |
| `APPSTORE_ISSUER_ID` | Issuer ID for the InfoHub team |
| `APPSTORE_PRIVATE_KEY` | Corresponding PEM `.p8` contents |
| `P12_BASE64` | Base64 distribution certificate **and its private key** |
| `P12_PASSWORD` | Password protecting that PKCS#12 archive |

The expected team is `UPDM24DCXU`, as in Momento's existing personal-account
release setup. Confirm that InfoHub's app belongs to this team before the first
upload. A company-team distribution certificate cannot be substituted. Never
revoke an existing certificate to work around a certificate limit. GitHub cannot
return previously saved secret values; find their original authorized source or
have the account owner configure them. Only copy credentials to this repository
with the owner's approval, since maintainers can use Actions secrets.

The native target bundles a required-reason UserDefaults privacy manifest and
declares only OS-provided, exempt encryption. Review the backend's collected data
and existing App Store privacy labels before a **public** release. The 1024px icon
is an opaque, losslessly rendered copy of the original logo;
`prepare_app_icon.swift` reproduces it when regenerating the project.
