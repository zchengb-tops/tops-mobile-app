# InfoHub native iOS

Native SwiftUI rewrite on `feature/ios-native-rebuild`. The React Native app and Android sources remain in place. Open **InfoHub.xcodeproj**, select the **InfoHub** scheme, then run on an iPhone or iPad simulator. No Metro, CocoaPods, or third-party runtime is required.

From the `tops-mobile-app` directory, build and launch on iPhone 18 Pro Max with:

```sh
npm run ios:native
```

To choose another installed simulator, use `npm run ios:native -- "iPhone 18 Pro"`.
The command reuses build output and restarts the app with the latest code. It does
not package or upload a release. It opens Device Hub or Simulator from the active
Xcode installation, without relying on the app's registered name.

## Platform and design

- Minimum iOS 17; Liquid Glass navigation surfaces on iOS 26+. The bottom bar uses the original Ionicons with icon-left/text-right items; the mini player sits above it. Earlier systems use standard materials.
- Three destinations: Discover, Subscriptions, and My Account. Native navigation stack, sheets, reordering and pull to refresh. Discover has a single compact channel bar, without an additional generic hero or search header.
- The bottom-navigation selection plate is capped at 108pt wide at the default text size and scales with Dynamic Type, without shrinking its full-width touch target. Channel plates retain their 4pt horizontal inset; both keep a 3pt vertical inset, 44pt minimum touch targets and existing spring transitions.
- Edge-to-edge editorial layouts: an inset glass channel rail above open hot lists/tables, article/video artwork, podcast rows with independent playback, and readable Arena metric cells. There are no enclosing rounded reading panels; glass is reserved for navigation, the mini player and playback controls.
- Two-finger pinch now zooms the live reading page into a scrollable overview of all enabled channel pages. Tap a thumbnail to expand its channel, spread two fingers to return to the selected page, or use the channel menu/close button without a gesture. The original pager remains alive, preserving vertical reading positions. Only transforms and opacity follow the gesture; reduced motion uses a crossfade. Manual list spacing remains in My, independently of this global zoom and font size.
- Native iOS 1.4 (26) adds GitHub Trending (daily/weekly/monthly), AI Analysis (intelligence/speed/task cost), and the extension-style editorial overview. Special-channel endpoints refresh in parallel and keep last successful data on individual failures. New channels merge into local/cloud-restored settings without resetting opt-outs, order, RSS or unknown fields. Codex Radar and the extension-retired AI News are not exposed in the mobile UI. Legacy RN/Expo/Android release configuration remains unchanged.
- The editorial overview has no repeated brand/page heading or category titles. Sspai, 36kr, NN/g and RSS form continuous article rows; a 15pt source logo and source name sit together above the headline in its text column, following the extension rather than occupying a separate leading column. There is no standalone article-source heading or extra channel gap. Existing headlines/metadata remain intact, with 44pt source targets and independently tappable covers/text for reading. Sina and TIOBE show five items, the market map twelve sectors, and other lists up to four items; TIOBE reuses the complete channel's table header (current/previous-year rank dates, language, ratings and change), including its stacked accessibility layout. AI Analysis retains all intelligence-chart models with horizontal scrolling, matching the extension rather than truncating at four. Available items are never padded with placeholders. Full channel feeds, ordering and subscription data remain unchanged.
- Overview article thumbnails retain a common 140pt width and 94pt minimum height, expanding to fill the complete source/headline/metadata row. Artwork crops proportionally without stretching; 36kr headlines are vertically centered with metadata at the bottom. Accessibility text keeps its existing stacked layout, and complete channel feeds retain their original cover dimensions. Overview article rows omit secondary summaries at all text sizes while retaining source, headline and publication/author metadata; complete channel summaries remain unchanged.
- The overview channel reuses the original colorful InfoHub app logo in the channel rail, menu, subscriptions and global overview thumbnails. Icon dimensions, selection plates and touch targets are unchanged. The sparkle-wand design files remain available but are not used by the overview channel.
- GitHub follows the extension's editorial hierarchy: the compact period selector sits beside the title when space permits, unboxed warm-colored top-three ranks lead a separate column, programming languages have neutral capsule tags, and a restrained star/growth column balances the right edge. Growth uses the extension's 12pt gray-blue star, 10pt semibold count and 10pt secondary period caption, with 6pt icon/copy and 4pt count/caption spacing; counts stay prefix-free and the complete spoken metric is retained. The redundant domain row is removed; the title still opens the source. Large text stacks controls and metadata without shrinking them.
- AI Analysis uses native Swift Charts column plots with zero-based axes, grid lines, provider colors and exact value labels. Bundled provider logos sit above model names under each column, with a neutral model symbol for unknown providers; monochrome logos use semantic dark-mode tint. The separate selected-model footer and instruction line are removed. Tap a column to open its model directly in the existing reader; swipe inside the plot to compare more models without changing channels. Column count adapts to available width and Dynamic Type, VoiceOver has named model/value actions, and the editorial overview reuses the same charts. The channel heading includes a trailing 56pt channel logo in its original purple, inspired by the extension; it reuses the bundled asset and is hidden from VoiceOver without changing the source link. Global zoom thumbnails remain non-navigating previews. Source units and backend data remain unchanged. APIs follow [Apple's Swift Charts interactivity guidance](https://developer.apple.com/videos/play/wwdc2023/10037/).
- Sspai's standard view follows the original image-left/text-right layout, with restrained rounded covers, regular 16pt headlines, aligned dates/engagement counts and faint separators. Compact keeps the same typography with smaller thumbnails; spacious and accessibility text sizes reclaim the full width. Morning-paper titles retain their original red prefix, and metadata can stack without shrinking text.
- Other standard-density feeds follow their original channel-specific compositions: Bilibili/36kr have left-hand landscape covers and their author/count or author/time metadata; 36kr omits the board label in both overview and complete news lists. Podcasts have square covers, author/duration and an independent progress-ring play control; Douban has portrait posters, release details and fractional star ratings; NN/g retains its reading-time/summary stack and video overlay; History uses a continuous timeline. Zhihu keeps regular headlines and right-side thumbnails; TIOBE shows month/year columns and colored changes. Stock restores acquisition time and the original seven-tone palette; RSS uses compact dot/title/date rows, displaying times when all items share a date.
- Douban stars share the extension's score-dependent palette in overview and complete feeds: gray-blue through 4/10, golden yellow below 8/10, orange from 8/10. Empty stars are muted; numeric scores use regular-weight semantic secondary text for a quieter light/dark presentation, retaining half stars and accessible rating labels.
- Arena uses the original provider identities and two-by-two right-hand metrics, with a compact Models/Labs selector and correct section counts. Known original vendor SVGs are bundled in the native asset catalog, without adding a runtime SVG library; unavailable/new vendors retain the original initial-letter fallback. Accessibility text sizes stack metrics and reclaim headline width.
- The bottom glass controls have no opaque tint or safe-area shelf. Content and semantic backgrounds continue behind them to the home-indicator region. Reduced transparency/high contrast retains a solid, legible fallback.
- My page has an open account header and three compact, neutral reading-preference controls, without an enclosing page card or repeated row dividers. Preferences switch to full-width rows on narrow screens or larger text. More lists subscription sync, feedback, website, terms, privacy and version in that order, without an extra About page. The version row also checks for updates and retains a new-version badge after dismissing an available update. Cloud sync keeps its separate native page; login, logout, confirmed cloud restore, legal documents and existing links remain available. All three scrolling surfaces keep the shared floating-footer clearance.
- Sina rows share the same system headline size, weight and line height. Unboxed rank numbers use Zhihu's red/orange/gold palette for the top three and secondary gray thereafter. Overview Zhihu ranks reuse Sina's unpadded numbers, typography and column width, aligning headline columns; complete Zhihu feeds retain their original padded bold ranks. Normal text sizes align numeric heat on the right without a repeated caption; accessibility sizes stack the complete headline and count. Compact/standard/spacious rows use 2/4/12pt vertical padding with at least 44pt touch targets. No enclosing cards or repetitive rules; heat remains labeled for VoiceOver and manual spacing never shrinks the font.
- Email login has two focused steps: email/consent first, then six separate native digit fields with automatic focus advance, backspace, whole-code paste/autofill, resend cooldown and a return-to-email action. The digit row wraps when needed for large text or narrow screens, without shrinking touch targets. The title has no explanatory tagline, and the toolbar has no keyboard Done button; scrolling dismisses the native keyboard. Animated logo sun/horizon artwork is anchored at the bottom, behind the keyboard; native focus, reduced-motion support and the existing endpoints remain in place.
- The full podcast player requests the large cover variant from the provider's recognized image hosts, including episodes whose HD field is empty and previously saved episodes. The existing cover remains visible while loading or if the large image fails. The same loaded HD cover supplies a static blurred, material-softened background in light/dark appearance; the transport controls reuse the app's Liquid Glass surface on iOS 26+ and standard material on earlier systems, with 44pt minimum touch targets. Reduced transparency or increased contrast restores opaque semantic backgrounds, and failed/loading HD artwork retains a neutral backdrop. Feed/mini-player image selection and playback state remain unchanged.
- Scrollable feeds, subscriptions, settings, and legal documents reserve the measured floating footer height plus 16pt of reading clearance. The space adapts to the player and Dynamic Type; footer-free sheets retain native margins, and opening the reader does not shift the underlying feed.
- Semantic colors, system fonts, Dynamic Type, dark/light/system appearance, VoiceOver labels, and system-managed reduced-motion/transparency behavior.
- Legal pages use open, readable typography with a prominent document title, accessible section headings and scaled paragraph spacing. Bundled agreement wording and lists remain unchanged; both My and login use the same view and preserve return navigation.
- Debug bundle ID: `cn.zchengb.infohub.native`, allowing side-by-side development. Release retains `cn.zchengb.infohub`. TestFlight signing is configured by the release lane, independently of Debug.
- API base is configurable through `APIBaseURL` in `InfoHub/Info.plist`; defaults to the existing production endpoint. No credentials in the project.

This is a runnable development version, not a parity-certified App Store release. Existing MMKV subscriptions and playback state are not silently imported; users can recover cloud-synced subscriptions through the same account. Decide and implement an upgrade migration before replacing the shipped app. The native app does not include Firebase analytics; revisit instrumentation and privacy disclosures before release.

Subscriptions retain the original channel names, descriptions and branding, with native toggles/reordering. The reader restores a top sharing entry and has no bottom toolbar; refresh, webpage back and Safari remain in its action menu. The previously approved My/login layouts, floating controls, 108pt navigation selection, two-step code flow and HD full-player cover are intentionally retained rather than reverted to the old app.

New RSS subscriptions are inserted at the top and revealed after the add sheet closes; editing existing feeds keeps their position, and cancelling does not reset scrolling. RSS channel icons use the saved `iconUrl` with original colors, while badges and failed-image placeholders reuse the extension's orange `rss-fill.svg`. Existing channel order and subscription preferences are not migrated or reset.

Featured RSS recommendations remain a native single-column list: original-color source icons fit inside 44pt plates, with compact titles/descriptions and a trailing selection indicator. Missing or failed icons fall back to the RSS symbol; accessibility text can wrap fully. Selection follows the current feed URL and only fills the form; Save retains the existing URL validation, duplicate check and recommendation metadata. Loading and empty states are explicit.

## TestFlight release

The existing **Deploy to TestFlight** GitHub Action retains its React Native/Expo
push behavior on `main`. Native publishing is **manual only**: select
`feature/ios-native-rebuild`, set `implementation` to `native`, and run it.
`validate_only` builds and tests on the hosted Xcode 27 runner without credentials
or an upload; leave it unchecked to actually publish.

The native job uses the checked-in Xcode project, not Expo, Metro, CocoaPods or
`generate_project.rb`. Fastlane is pinned by `Gemfile.lock`; it verifies the
existing InfoHub App Store Connect ID `6739748229`, increments the build above
the current TestFlight train and the local baseline, uses a dedicated
`InfoHub Native AppStore` profile, then waits up to 20 minutes for Apple to process
the upload. It never submits public App Store review or invites external testers.
Internal testing-group access must be verified separately after processing.

Required repository Actions secrets (do not commit them):

| Secret | Value |
| --- | --- |
| `APPSTORE_KEY_ID` | Existing App Store Connect API Key ID |
| `APPSTORE_ISSUER_ID` | Issuer ID for the InfoHub team |
| `APPSTORE_PRIVATE_KEY` | Corresponding PEM `.p8` contents |
| `P12_BASE64` | Base64 distribution certificate **and its private key** |
| `P12_PASSWORD` | Password protecting that PKCS#12 archive |

The expected team is `UPDM24DCXU`, as in Momento's existing personal-account
release setup. Confirm that InfoHub's app belongs to this team before the first
upload. A company-team distribution certificate cannot be substituted. Never
revoke an existing certificate to work around a certificate limit. GitHub cannot
return previously saved secret values; find their original authorized source or
have the account owner configure them. Only copy credentials to this repository
with the owner's approval, since maintainers can use Actions secrets.

The native target bundles a required-reason UserDefaults privacy manifest and
declares only OS-provided, exempt encryption. Review the backend's collected data
and existing App Store privacy labels before a **public** release. The 1024px icon
is an opaque, losslessly rendered copy of the original logo;
`prepare_app_icon.swift` reproduces it when regenerating the project.
